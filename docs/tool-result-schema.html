El LLM no copia precios. La tool guarda el ToolResult en state["resultado:<tool>"], el especialista responde solo un SpecialistReport con ids, y AgentTool le pasa ese estado al orquestador (ADK 2.13). El orquestador lee los precios del estado, nunca del texto.

Cómo se guarda en Firestore

Entra después de la fase 1 del roadmap. Hasta entonces el ToolResult vive en la sesión de ADK y sus métricas van al log. Firestore es la recomendación; la decisión sigue abierta.

jobs/{jobId}                 # una consulta de una persona · vence a los 30 días
  results/{tool}             # un ToolResult por tool: cada tool escribe el suyo
offers/{offerId}             # última versión vista de cada oferta
  history/{yyyymmddHH}       # precio por hora, para el historial del catálogo
merchants/{merchantId}       # comercio y su último TrustScore
products/{productKey}        # producto canónico, alias y mejor oferta
cache/{tool}__{queryHash}    # puntero a un results/{tool} reciente, con vencimiento
rates/{yyyy-mm-dd}__{source} # tasa del día

jobs/{jobId}

Clave: sha256(canal + message.id)[:32], el mismo hash que nombra la tarea de Cloud Tasks. Un reintento cae en el mismo job.

channel
whatsapp · web · mcp
userRef
HMAC-SHA256 del número con USER_REF_SALT. Nunca el número en claro
query
NormalizedQuery. De userLocation se guardan ciudad, estado y claves; lat/lng no
status
recibido · acuse_enviado · buscando · esperando_datos · respondido · fallo
toolsPlanned / toolsDone
se cierra cuando son iguales o vence deadlineAt
replyMessageId
wamid de la respuesta. Si existe, no se reenvía
matches
Match[], uno por oferta para esta persona (máx. 200)
best
offerId, priceUsd, merchantId
totals
latencyMs, credits, offers
vence: 30 días

jobs/{jobId}/results/{tool}

El ToolResult completo, ya enriquecido. Va en una subcolección para que las tools en paralelo escriban cada una en su documento y no compitan por el mismo.

El Merchant con su último trust. El id lleva el prefijo de la fuente (ig:bodegon). Firestore no acepta / en un id: web: usa el dominio.

cache/{tool}__{queryHash}

queryHash = sha256 de product.key, condición y toolVersion, más userLocation.cityKey solo en las tools que buscan por zona (Marketplace). La cercanía se calcula después, así que personas de ciudades distintas reusan el mismo resultado. Guarda jobId, status y expireAt.

class Model(BaseModel):
    model_config = ConfigDict(
        alias_generator=to_camel,
        populate_by_name=True,
        extra="forbid",
    )

class ToolResult(Model):
    job_id: str
    tool: str
    tool_version: str
    status: ToolStatus
    started_at: datetime
    finished_at: datetime
    offers: list[Offer] = Field(default=[], max_length=50)
    merchants: list[Merchant] = []
    evidence: list[Evidence] = []
    metrics: ToolMetrics
    errors: list[ToolError] = []

class SpecialistReport(Model):
    """output_schema del especialista."""
    tool: str
    status: ToolStatus
    offer_ids: list[str]
    note: str | None = Field(default=None, max_length=280)

# La tool guarda el resultado; el LLM solo ve ids:
tool_context.state[f"resultado:{tool}"] = (
    result.model_dump(by_alias=True, mode="json")
